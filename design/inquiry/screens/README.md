# Inquiry browser acceptance screenshots

**Synthetic Schwarzschild–AdS example.** These are unmodified crops of a running Atlas interface under a disposable DSH profile and private Chromium. The local text-only model supplied scripted turns, not reasoning about a real conversation. No URL was opened, paper retrieved, solver run or physical result verified. The chart draws the five invented rows in the fixture CSV. The report and review were authored by the test, not by researchers or real workers.

[Acceptance scenario](../../../test/inquiry-ui.mjs): `node test/inquiry-ui.mjs --capture` after building the client. It sends real UI input, follows a real workspace citation, checks the persisted correction, declines the first charter, requests teaching, then explicitly starts one separately reviewed charter with an edited first task. It verifies that the original discussion receives a selected report/review assessment and can explain the result without starting another team. Capture files are published only after the journey passes with no browser console, page or HTTP errors. Filenames with `1440` or `1024` refer to the viewport width; the PNGs are the visible app region, not the surrounding desktop. Nine screen points per crop must be hit-testable on the intended component before publication.

**Measured scope.** The question pair used two columns in a 697 px inquiry panel (768 px browser viewport) and one in a 485 px panel (500 px viewport), without page or component horizontal overflow. Sampled contrast for the Edit questions button was 7.99:1 by day and 9.14:1 at night; this is a spot check, not an accessibility certification. At a narrow 560 px viewport the native DSH sidebar can overlay the plot even though Atlas fits horizontally; do not infer that the whole workbench is obstruction-free on phones. The chart images instead show an unobscured real split pane at a wide viewport, with the cited notebook open beside it.
