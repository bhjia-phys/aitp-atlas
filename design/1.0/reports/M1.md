# M1 — Shell and visual system · 0.10.0 review candidate

**Review gate; not a release.** Local branch `redesign/m1-shell`, based on Atlas 0.9.2 `bc70ea7`. No merge, push, live installation or researcher data. Only synthetic research in a throwaway DSH profile; M2 and M3 are not implemented.

## Try it

From the source checkout, run `node build-client.mjs` and `npm run preview`. Open the exact private address it prints; select **Atlas** in DSH's sidebar. No API key or network model is needed. Starting a question talks to a local streaming mock, not a researcher’s account. Open Map → a topic, Focus the topic, then press Esc. Use the gold Atlas mark for commands and More → Keyboard shortcuts for effective bindings. Press `q` then Enter in the terminal to discard the fixture. A preview stages a copy: rebuild **and restart** after changes.

## Verification

- Every implementation checkpoint is rebuilt and checked with `npm test` and `npm run test:dsh` on an isolated staged snapshot. Real DSH 0.2.2-rc.3, no install into the user's profile. Visual verification is on the **integrated** candidate, not a separate visual claim for every intermediate commit. M0: 58 tests + 14 DSH checks.
- Offline assets: both protected WOFF2 routes return real font data; anonymous requests denied. The isolated browser loaded the Roman and Italic faces (HTTP 200, `font/woff2`). Nebula normal-vision adjacent minimum ΔE ≈17.3 in both moods; minimum across the protan/deutan simulations 11.1 night / 9.1 day; minimum contrast on actual surfaces 3.66:1 / 3.58:1. Not a validation of every color-vision deficiency.
- Added behavioral coverage for command ranking, Host shortcut collisions, Focus/sidebar ownership, timing and focus return of controls, v2 routing/migration/dirty buffers and reopen, sky geometry up to 360 topics, Desk attachments, legacy discussion/team projections and neutral review wording. Unit tests do not establish visual fidelity or PDF selection behavior by themselves.
- Browser acceptance is recorded below. The real GUI is distinct from the static design mockup and from headless DSH installer checks.

## Data and scope boundaries

1. **Continue** sorts legacy Atlas records by creation time, not an invented last-turn time. **Needs you** uses actual waiting Current work entries; **Running** uses live DSH rows for known Atlas sessions. Native team decisions, unread counts and a full persistent registry are later milestones. The UI does not simulate them. Relative file references are sent as pointers, not copied into notes.
2. **Discuss first, organize second.** You can draft a question without creating a task board. No change to research skills or automatic project planning here. The later research workflow should begin with a physics question, assumptions and a checkpoint the researcher can understand — not a task count.
3. **Changes on disk are not proof of authorship.** A wording fix is present; concurrent-review conflict handling and baseline retention remain M2 acceptance items. New host routes must respect real DSH registration semantics; legacy import must be idempotent per record, not only work for an empty database. M3 seat templates must carry a real prompt and respect routes the lead may actually delegate.
4. **Native host limitations.** Host sidebar and shortcut services are optional. Atlas does not manipulate an unrecognized frame, steal DSH's Ctrl+K, or claim browser-reserved keys that never reach a page. More → Keyboard shortcuts shows the effective set; menu buttons remain usable. Atlas theme applies to Atlas, not to DSH's surrounding sidebar.
