## 怎么看、怎么试

- 从项目目录运行 `node build-client.mjs`、`npm run preview -- --team`。打开启动器显示的**完整临时地址**，点 DSH 侧栏 **Atlas → Atlas ▾ → Teams → New team**。按终端给出的合成问题与 Done when，Topic 选 **Worm algorithm: equilibration and reproducibility**；选 **Theory and numerics**，移掉 theorist，保留 numerics 和 referee。直到确认 **Start the team** 才会创建 run 和会话。按 `q` 回车清理。
- 在房间里点成员星查看各自实际会话。输入 `@numerics` 单独给它发消息；未知名字不发给任何人。`Flow` 的报告与审阅可点开原文。普通 `npm run preview` 不启用工具调用，因此不能用其固定文本答复判断成员是否启动；自动浏览器验收另外放入报告、审阅和待回答的示例决策。

## 实现与偏差

| 要求 | 结果及判定依据 |
| --- | --- |
| TM-1…6：单一整合者、独立检查、分工与研究纪律 | **已写入章程和逐席任务，非权限沙箱。** 每席有角色卡、明确首个任务、允许文件与交付格式；保留未解决分歧，不自动平均或提交集群。新研究分支先讨论假设、决定性检查和失败标准，文献用于具体疑点。创建 lead 后，须核实当前课题笔记已被审阅基线覆盖，才发首条 brief；其他共享文件不能推断为已覆盖。是否遵守研究纪律和结论正确需要人的判断。 |
| TM-7…8：模板、核心/单次席位、模型 | **完成五种模板、可改席名/角色/时长；逐席模型选择有意收紧。** lead 读 DSH 实际模型和 effort 目录；缺失 route 不可启动。当前 DSH 公开的是 lead 模型目录，不是它可委派的 route 白名单。子席位省略 override，不假称能任选另一模型做 referee；role 和独立核查任务仍然分开。 |
| TM-9…14：目录、启动、核实、能力 | **完成。** 在所选 topic 的 runs 目录里排他建章程、状态骨架、roles、成员 work、reports/reviews/decisions。仅由绑定到当前根的 lead 开 Agent Teams 并收 brief；seat 来自它实际的 named subagent 投影，不从注册表虚构。失败显示做到哪一步，已接收的 brief 不重发。3 分钟核查以确认送达的时间为起点；没有可靠投影则为未知。 |
| TM-15…18：决策与控制 | **完成。** 决策按文件版本与明确选择写入，重复同一答复仅确认原记录，不重复通知；保存与 DSH 消息不是一个事务，送达未确认时明确区分。集群命令只展示，不执行。暂停、恢复和结束是给 lead 的请求，不声称强停子进程。Done 依赖 closing report 和可核查 idle。 |
| TM-19…24：Team room、成员页、响应式 | **完成核心路径。** 确认的 crew 决定星座；Flow 展示工作、报告、独立审阅与采纳，不从文字相似推断某人改了笔记。Board 来自 DSH（含 owner、依赖和写域）；Timeline 将 Atlas 观察时间与文件时间区分。Logbook 显示已核实决定、待比对笔记和缺席成员；宽度按房间而非整窗计算。`Run files` 提供当前团队文件与复制目录路径，而不调用系统文件管理器。 |
| TM-25…27：数据来源与耐久性 | **完成。** DSH 投影、有限制的 Markdown 元数据解析、独立的决定查询、事件 JSONL；无归属工件可读但不伪装为报告或裁决。核心操作校验研究根；切根前发出的请求不能把另一项目的决定塞进旧窗口。大报告或不完整状态文件不再掩盖完好的待答决定。 |
| DK-16…17、SH-8、旧团队 | **完成。** Desk、Topic、Teams、命令面板进入同一组队流程；保留唯一 DSH 侧栏。按根和会话证据单独导入旧团队、保留旧记录。旧团队只能看成员与板，不自动迁移文件或启动可写聊天。 |

- 隔离的本机 DSH + Chromium + 工具调用 mock：产品发出的完整首条 brief → 两个不同的真实 `numerics`/`referee` 子会话 → 两个子会话都调用 `read` 并收到各自角色卡的内容。打开各自 transcript 再核对；不是仅检查脚手架或 UI 标签。

## 已知边界

- 文件是研究事实的记录，不是审批前暂存，也不是作者认证。`accepted` 代表报告上有该状态，不代表已独立验证物理结论或有可归属的笔记改动。缺少可验证的 per-edit provenance 就不展示自动链接。
- 读取异常要区分「确知没有」与「无法核实」。同一决策目录内有文件读不全、无法证明 ID 唯一时拒绝写入。不承诺阻止同时使用外部编辑器在最后核对与替换之间改文件。队列/排他锁不自动抢占异常退出进程留下的锁。
- 演示的角色读取、会话路由与收件是真实 DSH 行为；研究任务、文件和回复为 fixture，不证明模型具备独立完成物理研究的能力。未合并、推送、安装到日用 DSH 或接触真实研究目录。
- 本报告是 M3 实施方送审材料，非 Claude 已签字。计划中的下一门为 M4：全屏幕可访问性、性能、能力降级和 1.0 使用文档。
