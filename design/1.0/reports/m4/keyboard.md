# M4 keyboard walk — installed DSH Web, isolated fixture

**Result:** passed on the staged 1.0.0 build (2026-11-18), client SHA-256 `3dc58c7127d9fe88098775c616da90bf1482c3a6c51776a6dfc7db92b8f52daa`. Run `node test/m4-keyboard-ui.mjs` after building the client. Two consecutive extended runs sent 848 and 858 physical key presses, with zero browser console errors, page exceptions or failed HTTP responses. The exact number varies with focus order; it is not a performance target.

The [test](../../../../test/m4-keyboard-ui.mjs) uses Chromium's keyboard input protocol only, starting at the fresh DSH notice and the native Atlas sidebar button. It does not call DOM `click()`/`focus()`, use mouse events or the clipboard, synthesize React state, or use a signed-in browser. Selectors and `document.activeElement` only observe which control ordinary Tab or arrow navigation reached. Chromium's actual accessibility tree supplies the role/name checks. The [shared driver](../../../../test/ui-smoke.mjs) closes the throwaway browser and DSH fixture even on failure.

| Flow | What the browser verified |
| --- | --- |
| DSH → Atlas → seven destinations | Tab/Enter accepts the fresh-profile notice and opens Atlas. ArrowDown opens destinations; Chromium exposes the named menu and all seven named menuitems. Arrow keys + Enter activate Desk, Discussions, Teams, Map, Library, Learn and Write tabs; Escape returns to the Atlas trigger. Alt+5 independently activates Library. |
| Palette → topic | The advertised command shortcut opens a named modal dialog with a results listbox. Tab and Shift+Tab stay inside; Escape returns to the original focus. Typing `#worm` and pressing Enter opens the fixture topic's actual text. |
| Final right pane → remaining tab | Opened a topic in the sole right tab, checked the installed shortcut sheet, and put actual keyboard focus on a button *inside* the right panel. With Ctrl+Alt+W already reserved, the sheet advertised Ctrl+Alt+Shift+W. That chord closed the right pane; `document.activeElement` was the remaining selected Library tab. Earlier integration candidates advertised browser-owned Ctrl+W or no binding; neither was accepted. |
| Map and Library controls | Switched the Map from its chart to the list and found the topology topic. Typed a nonmatching library filter and verified the actual fixture paper disappeared; clearing the filter restored it. |
| Learn → topic | Changed the native topic selector with Home/arrow keys. Opened the selected Worm algorithm topic and found its equilibrium-distribution content. |
| Write → TeX → Outline | Opened the fixture's linked draft from the Write list. Tab left the source editor; reverse Tab returned to it, then exited backward without changing the file text. Opened Outline and reached its separator by Tab. At a feasible interior split, ArrowRight changed 50% / 301 pixels to 51% / 307 pixels and ArrowLeft restored the ratio. The fixture source was not compiled; TeX distribution availability is not under test. |
| Desk → discussion → sources | Typed a question and used Enter to send through actual DSH. Focused an assistant file reference by Tab and used Enter to open the note. The paper link opens the offline fixture PDF: a rendered first-page canvas and selectable fixture text are present. |
| Reduced motion | With the Chromium preference set to `reduce`, the two actual UI moods were selected. Checked visible controls, tabs and SVGs in each: no CSS animation, positive transition duration or smooth scroll. This samples the rendered surfaces, not all possible plugin content. |
| Teams → assemble → room → member | With the sheet open, Tab completes a full forward cycle, Shift+Tab completes a reverse cycle, no step escapes, and Escape restores New team. Reopened by Enter and completed the form using text keys, Tab and the native select's arrows. The local mock's real DSH lead starts two named seats; each receives its actual role card. The member star has an exposed button name. ArrowDown opens its details, Escape restores the star, and Enter opens that member's real transcript. |

All research, sessions and model responses were fixture-only. This verifies the named keyboard routes and a sample of AX semantics, not external screen-reader speech, OS-wide shortcuts, exhaustive coverage of every dialog/control, visual contrast or a full accessibility certification.
